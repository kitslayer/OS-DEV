# Milestone 141 — SHA-384/512 + SHA-384 certificate signatures

**Goal:** broaden certificate-chain verification beyond Let's Encrypt. Many CAs
(Microsoft, and most ECDSA chains) sign with **SHA-384**, which the kernel didn't
have — so milestone 139/140 reported those links "unsupported." This adds the
SHA-512 family and wires SHA-384 cert-signature verification in.

## What

- **`kernel/sha512.c` / `sha512.h`** — SHA-512 and SHA-384 (FIPS 180-4): 64-bit
  words (fine under `-mgeneral-regs-only` — `uint64_t` lives in GP registers), 80
  rounds, 128-byte blocks, on-the-fly padding (incl. the two-block case),
  SHA-384 = the same core with a different IV truncated to 384 bits.
  **Host-tested**: matches OpenSSL/Python exactly on `""`, `"abc"`, and a
  block-crossing 200-byte message, for both SHA-512 and SHA-384.
- **`rsa.c`** — the PKCS#1 v1.5 verify was factored into a generic helper +
  `rsa_pkcs1_sha256_verify` / new `rsa_pkcs1_sha384_verify` (SHA-384 DigestInfo).
- **`x509.c`** — recognizes `sha384WithRSAEncryption` and `ecdsa-with-SHA384`.
- **`tls.c`** — `cert_sig_ok` is now a `switch` over the four supported sig algs:
  RSA/ECDSA × SHA-256/SHA-384. (For ECDSA-SHA384 with a P-256 issuer key, the
  48-byte digest's leftmost 256 bits are used; P-384 *keys* are still unsupported.)

## Verified — demonstrated on a real SHA-384 chain

- **www.microsoft.com**: `www.microsoft.com` (RSA, **sha384WithRSAEncryption**) ←
  `Microsoft TLS G2 RSA CA` ← `Microsoft TLS RSA Root G2` — **`chain: 2/2 issuer
  link(s) verified`**: the from-scratch `rsa_pkcs1_sha384_verify` validated the
  leaf's SHA-384 signature against the real Microsoft intermediate. (Not anchored
  — Microsoft's root isn't in our ISRG-only store yet — correctly reported.)
- **text.npr.org**: still `1/1` + **ANCHORED to ISRG Root X1** — the RSA-SHA256 +
  anchor path is unaffected by the refactor.

No panics. SHA-384 RSA chains now verify; the remaining gap for some EC chains
(e.g. example.com's SSL.com CAs) is **ECDSA P-384 keys**, a separate curve.

## Files
- `kernel/sha512.c`, `kernel/include/sha512.h` — SHA-512 / SHA-384
- `kernel/rsa.c`, `kernel/include/rsa.h` — `rsa_pkcs1_sha384_verify`
- `kernel/x509.c`, `kernel/include/x509.h` — SHA-384 signature OIDs
- `kernel/tls.c` — `cert_sig_ok` handles SHA-384 algorithms
