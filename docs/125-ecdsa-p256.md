# Milestone 125 — ECDSA P-256 signature verification

**Goal:** verify the *other* common certificate signature type. Modern TLS
certificates are increasingly **ECDSA on NIST P-256** (`ecdsa_secp256r1_sha256`),
so this adds P-256 ECDSA verification — completing signature support for both EC
and RSA (milestone 124) certificates.

## What it does

ECDSA verification on P-256 (secp256r1):

- **Field & point arithmetic** over the P-256 prime, built on the bignum
  library. Points use **Jacobian projective coordinates** (affine `(X/Z², Y/Z³)`)
  so point addition/doubling need no per-operation modular inverse — only **one**
  inverse at the very end (via Fermat, `Z^(p−2)`). Doubling uses the `a = −3`
  fast formulas; addition handles the infinity and equal-point cases.
- **`ecdsa_p256_verify`** runs the standard check: validate `1 ≤ r,s < n`,
  compute `w = s⁻¹ mod n`, `u₁ = z·w`, `u₂ = r·w`, the double scalar
  multiplication `R = u₁·G + u₂·Q`, and confirm `R.x mod n == r`.
- **`ecdsa_p256_verify_der`** first parses the DER `ECDSA-Sig-Value`
  (`SEQUENCE { INTEGER r, INTEGER s }`, stripping sign bytes) — the form TLS and
  X.509 carry signatures in.

Everything is integer-only (the bignum), so it's kernel-safe (no FPU).

## Verified — OpenSSL and fuzzing

- **vs OpenSSL:** generated 25 P-256 keys, signed random messages with
  `EVP_DigestSign` (ECDSA/SHA-256, DER output), and confirmed every signature
  **verifies** while a flipped hash byte is **rejected**.
- **Fuzzed:** 60,000 random/garbage DER signatures and public-key blobs — all
  cleanly rejected, **zero crashes** under ASan + UBSan.
- Compiles into the kernel.

## The TLS crypto + certificate toolkit is complete

A TLS 1.3 client's entire cryptographic and certificate-validation needs are now
in place and independently verified:

| role | primitive | milestone |
|------|-----------|-----------|
| key exchange | X25519 | 119 |
| record AEAD | AES-128-GCM, ChaCha20-Poly1305 | 120, 122 |
| hash / transcript | SHA-256 | — |
| key schedule | HMAC, HKDF, HKDF-Expand-Label | 121 |
| certificate parse | X.509 / ASN.1 | 123 |
| signature verify | RSA PKCS#1 v1.5 + PSS, **ECDSA-P256** | 124, **125** |

What remains for working HTTPS is purely the **protocol**: the TLS 1.3 handshake
state machine and record layer, wiring all of the above over the existing TCP
stack — integration work for a focused session, sitting on a fully-tested base.

## Review (bignum + RSA + ECDSA)

A read-only security review of the signature-verification code found **no
CRITICAL issues** — no forged signature is accepted, no out-of-bounds read/write,
and no infinite loop on malformed input. It confirmed: RSA PKCS#1 v1.5 is
Bleichenbacher-resistant (the recovered block must be exactly right-aligned with
no trailing garbage); RSA-PSS and ECDSA bounds and `r,s` range checks are
correct; the ECDSA point-at-infinity handling and the single-subtract `mod n`
reductions are provably sufficient; `rsa_pubkey_parse` and the DER readers are
memory-safe; and the bignum edge cases (zero/one modulus, exp 0, aliasing) are
safe. Its one MEDIUM finding — ECDSA didn't validate that the public key is on
the curve — is **fixed**: the verifier now rejects coordinates ≥ p and checks
`y² ≡ x³ − 3x + b (mod p)`, guarding against invalid-curve attacks. (Re-verified:
25 valid sigs still accepted, tampered + 60K fuzz inputs rejected.)
